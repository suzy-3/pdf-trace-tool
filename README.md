# PDFトレースツール

FastAPI・OpenCV・PyMuPDFによる、日本語のスキャンPDF補正・SVG変換アプリです。Sitesは使用しません。

## 起動（Python 3.12）

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

ブラウザーで http://127.0.0.1:8000 を開きます。単一ワーカーで起動してください。

## 操作

1. スキャンPDFをアップロードします（20MB以下、暗号化なし、最大100ページ）。
2. ページを選択し、傾き補正・ノイズ除去・線の鮮明化を設定します。
3. 「補正・SVG変換」で元図面と補正後を左右に比較します。
4. 選択中のページを補正PDFまたはSVGでダウンロードします。
5. 「図面を閉じる」で一時保存を削除します。

傾きはHough線分から±15度の範囲で推定します。ノイズ除去は非局所平均フィルターと微小連結成分除去、鮮明化はアンシャープマスクと大津の二値化を使用します。レンダリングは最大144dpi・約1200万画素です。SVGは黒線の輪郭をパス化し、穴を保持します。中心線、CAD要素、OCR、寸法認識ではありません。細線や小さい文字は設定により失われる場合があるため、比較画面で確認してください。傾き補正ではページ端が切れる場合があります。

出力PDFは選択中の1ページの画像PDFで、元の表示ページ寸法を保持します。元PDFの文字・注釈・レイヤーや複数ページ一括出力は保持しません。

## 一時保存・運用範囲

PDFと処理結果はプロセスメモリーに保存します（最大8文書、1時間）。処理結果のキャッシュは全図面合計128MiBまでで、古い出力から解放します。解放されたページは再変換してください。CAD処理中のマスクやベクトル中間データは権限を制限した一時ディレクトリに保存し、成功・失敗・キャンセル時に削除します。期限切れデータは次のAPIアクセス時に削除されます。再起動で消去されます。URLにはランダムな文書IDを使います。認証・永続保存・複数ワーカー共有は未実装のため、ローカルまたは信頼できる内部環境で使用してください。公開サービス向けの構成ではありません。

依存関係は `requirements-lock.txt` の検証済みバージョンに固定しています。

## テスト

```sh
pip install -r requirements-dev.txt
python -m pytest -q
```

テスト内で2ページのスキャンPDFを生成し、アップロード、ページ表示、補正、SVG/PDF出力、削除、傾き補正精度、ノイズ除去、空白ページ、不正入力、保存上限、有効期限を検証します。GitHub Actionsでも実行します。

API仕様: 起動後の `/docs`。

Chromiumをインストールした環境では、実ブラウザー操作も検証できます。

```sh
python tests/browser_smoke.py
```

既定ではPATH内のChromium、または `python -m playwright install chromium` でインストールしたブラウザーを使用します。別の場所の場合は `CHROMIUM_PATH` を指定してください。アップロード、ページ切替、補正画像表示、PDF/SVGダウンロード、モバイル幅、削除を確認します。

## CAD風清書（Issue #2 / Phase 1最小実装）

画面で「CAD風清書（中心線）」を選びます。APIは `/process` に
`{"mode":"cad_clean"}` を指定します（APIの既定値は互換性のため `legacy`）。
既存の輪郭変換も選択できます。

- 紙面の局所的な輝度ムラを補正し、薄い線を保守的に抽出します。
- Zhang–Suenスケルトンをグラフ化し、分岐・端点・閉路を持つポリラインにします。
  同一グラフ辺を一度だけ出力し、完全に一直線の頂点だけを省略します。
- 主要線は `fill="none"` のstroke SVGとベクトルPDFになります。
  **小領域（高さ12pt以下・幅40pt以下）は文字・点・短線の保護領域として元の画素を埋め込みます。**
  OCRではなく幾何条件なので、すべてがベクトルになるわけではありません。
- 原図忠実では線の整直・スナップを行いません。清書優先では長いパスだけを
  許容誤差内（最大0.75pt）で整理します。
  提案した中心線の全画素が抽出インク内に収まる場合だけ採用します。
  曲線や斜線の強制的な水平垂直化や、途切れ線の推測補完は行いません。
- 線幅・整理許容誤差はPDFのpt単位で指定します。
  ノイズ強度はpt²相当の面積閾値で、縦横2pt以内の点状領域だけを除去します。
  句読点を消す可能性があるため、ノイズ除去の既定値は0です。
- 回転時は余白を拡張し、元の線を切り取らず、縮尺と縦横比を維持します。
  出力PDFのページサイズも拡張されます。従来方式の回転は従来どおりです。
- 「重ね合わせ・差分確認」で回転後原画と比較し、透明度を調整できます。
  差分の赤は欠落候補、青は追加候補（距離許容は1レンダリングpx）。
  太線の細線化や指定線幅によるはみ出しも候補に含みます。

### 制限と残課題

前景30万画素・CAD専用300万画素の制限を、重複付き小領域の順次処理で置き換えました。
既存レンダリングの144dpi・約1200万画素の上限を維持し、CAD側でさらに縮小しません。
回転後の作業画像は2000万画素、SVG本体は64MiB、細線化は256反復の安全予算を設けています。
超過時は原因と対処を日本語で案内します。画面には段階・進捗率・処理領域数を表示します。
認証や永続保存、社内公開の構成は追加していません。

細線化によって太線の端点や交点が数画素移動する場合があります。
文字が大きな線に接続している場合は小領域保護の対象外です。
低コントラスト・広い灰色領域・写真・印影の完全な保持は保証できません。
保護領域は元の濃度・太さを保持するため、主要線と同じ線幅にはなりません。
差分の確認と原画参照は必須です。実図面での寸法精度や専門サービスと同品質を
保証するものではありません。

手動での追加・削除・移動UI、離れた線の連結、CAD意味認識、DXFは後続対応です。
線分連結閾値に代えて、今回のUIは安全な「線分整理の許容誤差」を提供します。
手動修正を実装する際も、ユーザー操作と自動推測を明確に分ける必要があります。

含まれ、追加候補数には設定した線幅の広がりが含まれます。


## 大規模図面の分割処理と進捗API

384×384pxの中心領域を順次処理します。前処理には背景補正カーネルと
文字保護領域の大きさに合わせた重複領域（通常83px）を設けます。
文字や点状ノイズの連結成分が重複領域端に接する場合は、小領域と誤認しないよう
保護判定から除外します。全体を縮小して30万画素に合わせる方式ではありません。

細線化は1pxの重複領域を参照し、Zhang–Suenの各サブ反復が全領域で終わってから
次の状態へ切り替えます。独立したタイルを近接距離で貼り合わせる方式と異なり、
太線や斜線の境界でも全体一括処理と同じスケルトンになります。
グラフ化は2px重複付きの領域単位です。境界の各辺は上側／左側の端点を含む
領域に一度だけ割り当て、共通のグローバル座標で出力します。
境界の端点はスナップで動かさず、隙間の推測補完も行いません。

全ページのPythonグラフをメモリに保持せず、マスクはディスクのメモリマップ、
SVGの中間文字列は一時ファイルに逐次書き込みます。文字保護画像と差分画像も
領域単位で作ります。原画・最終描画・圧縮された出力のメモリは依然として
ページ面積・出力サイズに比例します。一定メモリで無制限の図面を処理する機能では
ありません。処理は同時1件に制限し、処理中の追加要求は日本語のHTTP 409を返します。

画面は次の非同期APIを使用します。従来の同期 `/process` APIも維持しています。

1. `POST /api/documents/{id}/pages/{page}/jobs` に従来の処理設定を送信（202）。
2. `GET /api/documents/{id}/pages/{page}/jobs/{job_id}` で
   `state`（running/done/failed）、`stage`、`percent`、`completed`、`total` を取得。
3. doneでは `result` に処理結果の概要、failedでは `error` に日本語の原因を返します。
4. 成功後は従来どおり `corrected.png` / `trace.svg` / `corrected.pdf` を取得します。

進捗率は作業段階の概算で、完了領域数も併記します。失敗時は古い出力へのリンクを
無効にします。図面削除時は次の進捗更新で処理を中止し、出力を復活させません。
ブラウザを閉じてもサーバーの処理は継続します。再起動後のジョブ復元は未対応です。

### 大判平面図の回帰テスト・測定

`tests/test_tiling.py` は前景30万画素超の384万画素の平面図を生成し、非同期処理、
境界を通る寸法線、SVGのstroke幅、PDFのページ寸法とベクトル出力を検証します。
異なる領域サイズで細線化が一括処理と一致し、元のグラフ辺を欠落・重複なく
出力すること、境界上の平行線・交点・小文字の保持も確認します。
メモリ不足・一時ファイル保存失敗・予期しない例外は日本語表示を検証します。

`python tests/benchmark_tiling.py` は1120万画素・前景約266万画素の合成平面図を
別プロセスで処理します。[実測値](docs/examples/tiled-measurements.json)を保存しています。
このクラウド環境では約8.25秒、プロセス最大RSS約290MiB、88領域でした。
グラフ入力の最大面積は150,544px（388×388）で、図面全体の前景数に依存しません。
実測はライブラリ等を含むプロセス最大値で、実図面や全環境の速度・精度・上限を
保証する値ではありません。自動テストでは最大RSS650MiB未満も検証します。
